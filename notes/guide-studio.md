# Alternative Dublin Guide Studio

A working prototype for Event Guide Picks and What’s New in Dublin. Both series use one renderer with shared typography, spacing and colour controls. Like Tape Type and the event guide, it is built to live on GitHub Pages at https://shaunphh.github.io/guide-studio/ (see Hosting).

## Run

```sh
npm install
npm run dev
```

Open http://127.0.0.1:5193 (keep this exact address: saved guides belong to it, and `localhost` or another port starts an empty library). `npm run build` checks types and creates `dist`; `npm test` verifies importing, saved project validation and the ZIP format. Dependencies are the project’s own (`package-lock.json`, since 2 October; before that node_modules was a link into a temporary Tape Type folder). If `npm install` stops with “Cannot read properties of null (reading 'edgesOut')”, that is an npm 10 bug: run `npm install --legacy-peer-deps`.

## Hosting

The repo deploys itself: every push to `main` runs `.github/workflows/pages.yml` (install, tests, build) and publishes `dist` to GitHub Pages, as the event guide does. The build is served from `/guide-studio/` (the repo’s name; `vite.config.ts`, override with `BASE_PATH`), so files from `public/` are reached through `asset()` in `render.ts`, while saved pages keep root paths such as `/photos/pub.jpg`. `npm run build` then `npx vite preview` serves the build the same way locally, at http://127.0.0.1:4173/guide-studio/.

The hosted site keeps its own library, separate from the local one at 127.0.0.1:5193 (saving is per browser and per site). To move a guide across, use Backup on one and Restore on the other.

## Try

- Start with the clearly labelled sample guide. Sample stories/photos are layout examples; replace them before publishing.
- Switch Picks / What’s New. Story content, crops and event details survive either direction.
- Edit the cover and date. Use two photos side by side or top and bottom, each with its own crop. The scrim starts at 30% and remains adjustable.
- Picks omits supporting copy; What’s New places it at the bottom over the photos. Both use a dark divider and a top-right logo. Logo and arrow are yellow for Picks, white for What’s New.
- Four-photo, logo-position, mark-colour, divider-colour and subtitle-position alternatives stay visible but disabled. Add `?unlocked` to the local URL for design exploration. These are editorial guardrails, not access controls. Hidden photo slots and supporting copy stay saved.
- Select a story to edit its title, copy, emphasis, photo, footer and picture height. Reorder, duplicate and add stories. Under the story field a count follows the page as it is drawn: the words, and about how many more the room left would take, or how many it is over (18 October). The goal for the doc is 80 to 90 words, about 80 under a three-line headline; Import copy's review says the words of each story and flags any over 90.
- ↑ and ↓ step through the pages in the sidebar's order, as clicking them does, except while typing in a field, on a slider, in a dialog, or nudging the tape box.
- Upload a cover image directly into either photo slot, or use an eligible story image. Uploads and cover crops stay independent of inside pages. Since 18 October a photo can also be dropped on the page, on a photo button or on a story's card in the list (that story gets it), or pasted with ⌘V after Copy image on a website: no download needed. An image dragged straight from a website is fetched when its site allows; otherwise the toast says to copy and paste it.
- Adjust tape background opens a temporary bounding box. Drag the box or its handles, enter exact X/Y/width/height, and copy the values. Each series keeps its own dimensions per guide. The outline never exports; the adjusted background does.
- The sample stories run about as long as a real one (~485–525 characters, the length the team writes; a page holds 12 lines under a one-line headline, 10 and a paragraph break under two). My guides → New guide → “Start from the sample pages” makes a fresh copy. House style → Make a full-pages preview runs a copy of the open guide to the very last line, using the renderer’s actual wrapping to stop above the footer.
- Drag on the page itself: photos to reframe them, the cover headline up and down. The sliders follow along; each drag is one undo step. Every inside picture is the house height (House style); `?unlocked` lets a page change its own, by slider or by dragging the picture’s bottom edge.
- Two Instagram handles: type them with a space between, and they stack in the footer.
- Cover choices omit the Late Night Art demo poster. New sample covers use the neutral interior and Dublin river photos. On any story, turn off “Offer this photo for the cover” for posters or graphics; the inside page keeps its image.
- House style controls update all locally saved drafts. A custom story picture height is retained.
- Import copy: labelled plain-text sections separated by `---`, Markdown headings, or CSV with Title/Name, Body/Description, Handle/Instagram Link, Date, Time and Venue/Location columns. A guide doc pasted from Google Docs (5 October): each story starts at a `Title:` line (or after a line of dashes, which Docs may have turned into — or –), then `Instagram:`, `Date:`, `Time:`, `Venue:` and `Text:`; paragraph breaks are kept. The dialog's “How to set up the doc” says so, with a template to copy (`DOC_TEMPLATE` in main.ts, also “Use an example”). Picks come from a doc like this or from the events Sheet's TOP PICKS and BLURB; TOP PICKS gets ticked either way, for the website. The team's weekly What’s New doc pastes as it is (8 October, from WNID WK41): a heading per story marked ✅ done, 🟠 waiting for review, 🔴 not started or ❌ deleted, then `Written by:`, `Brief:`, `Link:`, `Instagram:`, `Text:` and `Newsletter Text:`. Only ✅ stories come in, with their `Text`; the review names the ones left out, and the key and notes above the first story are skipped. That mode needs a status heading and one of the doc's own labels (Written by, Brief, Newsletter Text), so a ✅ inside an ordinary guide doc stays text. An Instagram line that is a website gets a warning. Fit, measured 8 October: 89 words (about 560 characters) under a one- or two-line headline, about 80 under a three-line one (headlines from about 58 characters); in WK41, 6 of the 15 ✅ stories ran into the footer. Review before creating a new guide or appending stories. Existing manual edits are never overwritten by an import. Since 18 October a doc's Section, Event (the Sheet's ID), Alt text and Photo credit lines land on the story's own fields (the panel shows them under the photo and under For the website), and Source, Link, Photo, Website text, Pick note and Note lines are skipped as notes in either kind of doc, so the team's template docs (What's New, Top Picks) come in clean.
- A Google Sheet's link (since 5 October), loaded the way the event guide loads the events Sheet (`src/sheet.ts`: Google's GViz endpoint as a script, then the tab's CSV export; the Sheet must be shared with anyone who has the link). Any Sheet's link works, and each kind of guide remembers its last one in this browser. A stories Sheet has one story to a row under Title, Text (or Blurb), Instagram, Date, Time and Venue; date and time cells come out as footers write them (9 Oct, 8pm), and the dialog's “How to set up the Sheet” says how to lay it out (Plain text Date and Time columns, because Google drops a text cell such as 22–26 Oct from a column it holds as dates, and the import warns when that may have happened).
- The events Sheet, by link or as a CSV, the same file the event guide takes (Google Sheets → File → Download → CSV; since 5 October): read the way the event guide reads it (weekday rows, approval, dates). A Picks guide takes the approved rows with TOP PICKS ticked (leaving out any whose STATUS says Cancelled or Postponed, as the event guide does), filling each story's title, handle, date (9 Oct), time (8pm) and venue; the text comes from a BLURB column if the Sheet has one (the website's one-or-two-sentence DESCRIPTION is only a fallback, wherever it sits in the Sheet), or is written here. A What's New guide says to use its own stories Sheet or paste from the doc, since the events Sheet has no What's New column.
- Export one PNG or an ordered carousel ZIP, at 1× or 2×. Missing photos/content and overflowing pages block export and take you to the page needing attention. The ZIP carries `captions.txt` (18 October): each page's alt text and credit, and every handle to tag, so the person posting pastes instead of retyping.

## Saving

The complete library, including uploaded image data and separate crops, is saved in IndexedDB. Save failures are visible. This is local to the browser and origin (including port): there are no accounts, cloud storage or cross-device collaboration, apart from the team library below once it is set up. Use Backup for a portable `.guide.json` containing the complete issue, actual image data and house styles. Restore creates a new issue and explicitly lets you choose whether to apply its saved styles globally. Undo/redo is available during a session; it is not a persistent version history. Browser storage clearing removes local drafts, so keep backups for important work. Avoid editing the same local library in multiple tabs simultaneously.

## The team library

Since 18 October a guide can also live on the team library, a Supabase project, so two people can work on the same guide from different browsers, taking turns. It is off until the build has the project's address and anon key (`.env.example` says where they come from; the published tool takes them from the repository's Actions variables, see `.github/workflows/pages.yml`). Set it up once:

1. Create a project at supabase.com and run `supabase/migrations/0001_guides.sql` in its SQL editor: the `guides` table, the `team` guest list, the public `guides` bucket for the photos, and the policies that let only signed-in emails on the guest list read and write.
2. Add the team's emails to `team` (lower case). Authentication → URL Configuration: the site URL `https://shaunphh.github.io/guide-studio/`, and `http://127.0.0.1:5193/` under Redirect URLs for the dev server.
3. Project Settings → API: the Project URL and anon key go into `.env.local` for the dev server, and into the repository's Actions variables (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) for the published tool.

Then **Sign in** in the top bar sends an email link; opened on the same computer, it signs that browser in, and the session stays until Sign out (in My guides). My guides lists the team's guides under this browser's, newest first, with who saved each: **Open** takes a copy into this browser, linked to its row. **Save to team** (the top bar, or My guides) sends the copy back: photos still held as data go to the bucket first, under the guide's id, and the copy keeps their addresses, so it gets small; a save that lands after someone else's asks whether to overwrite the team copy or keep yours as a guide of its own. The save line under the guide's name says where the copy stands ("team copy: jack, today 14:02", or "changed since the team copy"). Export, Backup and Restore are as before; a backup folds the bucket's photos back in as data, so the file stands on its own. A browser that isn't signed in loads none of this (`src/team.ts` is a chunk of its own). The free plan's limits, 1 GB of storage and 5 GB a month out, fit a few guides a week; the photos are the cost, about half a megabyte each.

For the posting phone: instagram.com posts carousels from a Mac, so the ZIP can go straight up without the phone; or sign the phone's browser in, open the team guide there and export.

Tried on the real project on 18 October (project `alternative-dublin`, West EU, Ireland): sign-in by link, Save to team, a dropped photo going to the bucket and coming back as a public address the export canvas can draw, the team list, and the cleanup of a photo no longer used. Opening a guide from a second browser was not tried that day. That evening Save to team on a guide whose row already existed (the sample guide's fixed id, or a copy that came in by backup, which strips the link) hit the row's primary key; now it comes back as a conflict to settle, Overwrite or Keep mine as a copy, like a save that lands after someone else's. Two things to know: Supabase's built-in mailer sends only a couple of sign-in links an hour on the free plan (it says "email rate limit exceeded"), so before the team signs in, give the project its own sender under Authentication → SMTP settings (Resend's free tier is the usual choice; a domain record and ten minutes) and raise the limit under Authentication → Rate Limits. And the email link opens in the computer's default browser, so to sign a different browser in, copy the link's address out of the email and paste it into that browser.

## The shared AD tokens

The house style starts from the values every Alternative Dublin tool shares: `src/ad-tokens.json`, copied unchanged from Tape Type with `src/adTokens.ts` (how the tools read it) by `node scripts/sync-tokens.mjs`, which since 18 October also copies the tape engine into `src/tape/` (see Reused foundations). The colours, type sizes and weights, margins, picture height, safe area and mark sizes come from it; House style edits still adjust a library's own copy. To change a shared value, change it in Tape Type, then sync. Since the evening of 18 October the page number is 44px like every cover tag (38 before), and the footer takes the meta grey of the page's ground (`meta-on-light` #666363 on Picks pages, `meta-on-dark` #7f7c7c on What's New's dark ones; one #7f7c7c before) at 108, a notch under SemiBold.

## Reused foundations

- `src/tape/geometry.ts`, `types.ts`, `settings.ts`, `photo.ts`: copied unchanged from Tape Type for seeded tape geometry and crop calculations, by `node scripts/sync-tokens.mjs` since 18 October 2026 (last synced from `b949c84`; before that a hand copy of `0615b68`, from before Tape Type cut its eyebrow tags). `src/tape/adTokens.ts` is Guide Studio's own line pointing the engine at the tokens copy above. The existing tools are untouched.
- `src/event-source.js`: Event-guide’s CSV parser. The new importer supports undated stories and longer descriptions instead of enforcing the weekly event schema.
- Barlow fonts, logo and swipe arrow: Tape Type’s bundled assets.
- `BarlowGX-Normal.ttf`: Event-guide’s width-pinned variable Barlow, using its native 22–188 weight axis. All upright text is drawn from it (`src/barlow.ts`). Inside titles start at 168, the story-title weight every AD tool shares, and the cover date at 166, ExtraBold, the weight of every AD tag; both keep fine weight controls in House style.
- Sample photography: existing Tape Type templates.

The prototype uses the same canvas drawing for previews, thumbnails and exported PNGs. Fonts and images are local; export has no network service dependency. `src/zip.ts` writes stored ZIP records (PNG is already compressed).

Approved type defaults: covers 196px Bold, −3% tracking and 85% line height; supporting copy 46px Medium; the cover date a tag, ExtraBold capitals on clean-cut tape (Tape Type’s eyebrow); inside body 38px Regular (400); inside titles 64px capitals at the variable font’s 168, Normal width, zero tracking, under 500px pictures; footer Condensed SemiBold 36px (42px since 18 October 2026, at 108 since that evening). Body colours are #4B4A4A on light and #C2C2C2 on dark; the AD palette is #F0F0F0 / #101010 / #FFED1F. The two tape backgrounds have different padding for optical balance: around the default headlines, Picks is 639 × 601 and What’s New 689 × 617, centred, with the cut’s wider strip at the bottom. Earlier prototype libraries receive these typography defaults once; subsequent adjustments, copy, photos and crops are preserved.
